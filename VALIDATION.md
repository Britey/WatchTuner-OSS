# Development and validation

## Commands

Run from the repository root on macOS 15 or later with Swift 6 and Xcode:

```sh
swift test --configuration release --jobs 2
python3 Scripts/check-watch-production.py
python3 Scripts/audit-pitch-dependencies.py
python3 Scripts/test-audit-pitch-dependencies.py

xcodebuild -project WatchTuner.xcodeproj -scheme WatchTuner -sdk watchos -destination 'generic/platform=watchOS' -derivedDataPath .build/Device -jobs 2 CODE_SIGNING_ALLOWED=NO build
xcodebuild -project WatchTuner.xcodeproj -scheme WatchTuner -sdk watchsimulator -destination 'generic/platform=watchOS Simulator' -derivedDataPath .build/Simulator -jobs 2 CODE_SIGNING_ALLOWED=NO build
```

Run the Watch UI tests from the shared WatchTuner scheme on a simulator. Test mode uses generated input. Simulator playback is muted at the output boundary.

`python3 Scripts/generate-project.py` regenerates the Watch project and shared scheme. To inspect a built app, add `--bundle 'path/to/Watch Tuner.app'` to the dependency audit, which inspects the Mach-O files inside the app and checks the source inventory and Pitchy attribution.

## Known failing tests

Three strict production-pipeline cases are known to fail on macOS:

- `ProductionPipelineTests.testBrightLowVocalRecallAtDiagnosticAndSupportedTapCadences`
- `ProductionPipelineTests.testBrightStationaryVocalKeepsRootInsteadOfSecondHarmonic`
- `ProductionPipelineTests.testBrightUpperVocalVibratoAvoidsWrongHarmonics`

They expose rejected bright vocal input or confident readings at the wrong harmonic. The suite retains the original assertions and tolerances.

## Coverage

The test inputs are synthetic signals generated by the test source. Tests cover capture continuity, configuration changes, lifecycle, input leveling, tone controls, metronome timing, and selected pitch cases. The production Watch target compiles the Pitchy adaptation. Offline tests also exercise the retained harmonic estimators.

Physical Watches are needed to evaluate microphone accuracy, speaker and Bluetooth playback, Crown response, minimum-OS behavior, wrist-down audio delivery, battery use, and thermal behavior.
